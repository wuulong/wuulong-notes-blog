在鹿野高台的咖啡廳中，享受著雨中的美景，我完成了一件惦記已久的大事：學著在 GCP 上為我的數位助理「龍蝦 (Lobster)」建立新家，並賦予它一套完整的「自律邏輯」。

過去在本地端跑 Agent，總會遇到資源吃緊、連結中斷或是紀錄碎裂的問題。這次，我決定徹底工程化，從底層硬體到頂層治理，一次到位。

### 1. 給龍蝦一塊夠大的地：硬碟擴展 (50GB)

在雲端建構 Agent，最怕的是跑著跑著「腦力空間」不足。我將 GCP VM 的磁碟從原本緊繃的 20G 直接 Resize 到 50G。看著 `resize2fs` 跑完，空間瞬間釋放，那種「數位擴疆」的感覺非常扎實。50GB，足夠讓龍蝦在未來存放大量的台東文獻與 GIS 數據。

### 2. 雙腦聯通：Gemini 3.1 + n8n + Discord

這次的技術架構我採取「解耦設計」：
*   **大腦 (Thinking)**：採用最新的 **Gemini 3.1 Flash Lite**。它反應極快，且 Function Calling 的穩定度令人驚豔。
*   **執行 (Execution)**：透過 **n8n** 建立一個專屬 Webhook。

現在，我只要在腳本裡下指令，Agent 就會自己思考，然後調用我的 Discord 工具。當我在 Discord 的「閒聊」頻道看到龍蝦發出的第一則建置總結報告時，我知道這條「思考與執行的鏈條」已經打通了。

### 3. 三位一體：讓 Agent 學會「自我治理」

但我最在意的不是它能發訊息，而是它能「自律」。我將我一直堅持的 **「三位一體 (Trinity Suite)」** 治理框架寫進了龍蝦的基因：

1.  **帳本 (Task Ledger)**：它做事必須要有 Task ID。
2.  **日誌 (Work Log)**：每一步動作都必須留下 Facts 紀錄。
3.  **報告 (Task Report)**：完成後必須產出成果報告。

我為龍蝦寫了一套 **「自我治理套件 (Governance Suite)」**。現在當我叫它做事，它會先自動去 `TASKS.md` 登記 ID；事成之後，它會自己寫好報告、更新日誌，然後——這最關鍵——它會**自動執行 Git Commit & Push** 把這一切同步到我的私人 GitHub 倉庫。

### 4. 每日晨報：早安，龍蝦

最後，我設定了一個 `CronJob`。每天早上 07:00，龍蝦會主動「考古」它昨天的工作紀錄與任務清單，幫我產出一份「晨間戰略簡報」發到 Discord。

這意味著，我不再需要每天回想「昨天做到哪裡」，這隻龍蝦會主動把進度與卡點推到我面前。

### 結語：從工具到代理人 (From Tool to Agent)

這場建置不只是裝軟體，而是在雲端建立一個**具備戰略意識的數位孿生體**。它不僅能執行，還能透過版本控制留下演化的足跡。

下一個階段，我準備把 `bmad-pa` 裡的 GIS 知識庫跟台東歷史文獻餵給它。當龍蝦擁有了治理意識與深厚的知識庫，它就不再只是一個腳本，而是我數位人生旅途中，最可靠的領航員。
