> 本文記錄了《企業生成式 AI 轉型》方法論中，關於『個人為主，團隊為原型』的首次實體化實驗。

回顧這些日子以來，我與 AI (Antigravity) 的協作已經達到了一種近乎肌肉記憶的流暢感。從建立 [TMUX 自動化工作空間]、使用 Hammerspoon 打造「2+1 快手」，到用 `TASKS_LEDGER` 與 Mermaid 畫出戰略版圖，這是一套高度個人化的超級沙盒 (PA Sandbox)。

但問題來了：**如果我是一個超級個體，當我們要把這種力量擴展給一個 3 到 5 人的「超小型團隊 (Nano-Squad)」時，該怎麼辦？**

總不能要大家都學會寫 Python 腳本，或是用我特製的 Hammerspoon 快速鍵吧？

這就是這次 **團隊 AI 協作中樞實驗計畫 (SyncHub Prototype)** 誕生的背景。

---

## 理論基石：碎形邏輯與單一真相來源 (SSOT)

在《演化路徑：企業賦能的碎形邏輯：個人為基，團隊為原型》第 0 章中，我們定義了企業轉型的最小實踐單位：**超小型團隊 (Nano-Squad)**。

如果企業是由個體組成的碎形，那麼團隊管理與個人管理的架構就應該長得一樣。

這次的實驗，我們徹底拋棄了 LINE 或 Discord 這種容易造成「資訊孤島」與「語意發散」的即時通訊軟體作為真相來源。我們將 **GitHub (Git 檔案系統)** 確立為團隊的唯一真相來源 (Single Source of Truth, SSOT)。

所有的共識、決策、任務進度，都必須落地為 Markdown 或 YAML 檔案。

## 創新機制：非同步的「脈絡拋接 (Inbox / Outbox)」

為了消弭「團隊強制同步」帶來的摩擦力，並且保護個人的「AI Sandbox」實驗空間，我們設計了一套極其優雅的對合機制：

1. **個人主權區 (`members/{name}/workmgr/`)**：每一個團隊成員都有自己的安全區。你在這裡用你習慣的法子、自己的 ChatGPT/Claude 來打草稿、做研究，沒人會管你。
2. **對合與裁決 (`sync/outbox/`)**：當你覺得任務完成了，或者卡關需要團隊幫忙時，你（人類）必須下達「裁決」。把你的精華整理出一個 Payload，丟進你的 Outbox。
3. **戰略大腦 (`workmgr/inbox/`)**：團隊級別的 AI (SyncHub)，就像一個數位幕僚長。它會定時去各個成員的信箱收信，檢查有沒有語意衝突？有沒有偏離 Roadmap 戰略？然後自動將這些進度整合成團隊今天的小報，並刷新總任務帳本 (TASKS Ledger)。

這套機制的精妙之處在於：**它將微軟或 Google 提倡的 Multi-Agent System (MAS) 本地化到了檔案系統上。** LLM (大型語言模型) 原生就非常擅長讀取這種純文字的檔案結構！

## 個體的高效手感，化為團隊的標準武備

在最初的設計中，團隊的工作流範本還是偏向傳統的單卡式 (Task Card) 思維。但這完全不符合我習慣的「戰略全局導向與敏捷紀錄」打法。

因此，就在今天早上，我與 Antigravity 直接將原本只存在我腦海與個人專案中的高效兵器，重構並封裝成了團隊的標準範本：

*   **TASKS_LEDGER_TEMPLATE**：直接廢棄單卡，改用「總帳本」模式，讓團隊能一眼看盡正在執行與待處理的任務，並加入了 AI 來幫忙抓取對合路徑 (Sync Hook)。
*   **ROADMAP_TEMPLATE**：將 Mermaid 的戰略腦圖、因果鏈與演化時間軸列為標配，讓團隊不只低頭做事，還要抬頭看戰區羅盤。
*   **WLOG_TEMPLATE**：把工作日誌升級。不只是記流水帳，而是要求留下「下了什麼指令」、「改了什麼檔案」以及發生什麼「關鍵轉向 (Pivot)」，並在提交前加上「✨ 團隊對象勾稽」防呆機制。

## 實作經驗：與 AI 協作建構團隊基石

回顧今天早上啟動這項實驗的實作歷程，其實本身就是一次精彩的「人機協動 (Human-AI Collaboration)」。

一開始，我給了 Antigravity 一個模糊的概念：「我想給這場實驗取個名字，並建立一個 GitHub Repo」。接下來的發展完全超乎預期：

1.  **名稱收斂與架構生成**：我們迅速將名稱鎖定為 `synchub-prototype`。接著，AI 根據《企業賦能》第 0 章的理論，主動規劃出了具備「碎形對稱性」的目錄結構 (`workmgr/` vs `members/`)。
2.  **遇坑與自救**：在設定 Git Submodule 時，我們遇到了空白 Repo 導致的 `fatal` 錯誤。有趣的是，AI 理解了問題，主動幫我在 `/tmp` 建立初始化 commit 並推送到遠端，完美化解了技術卡點，讓我不必為了瑣碎的 Git 排錯中斷思緒。
3.  **範本進化與重構**：這是我覺得最精彩的部分。原本 AI 產生的任務範本是單張表單 (`TASK_TEMPLATE`)，這讓我感到彆扭。當我要求 AI 去檢視我慣用的 `TASKS.md` 總帳本與充滿 Mermaid 的 `ROADMAP.md` 後，它立刻「頓悟」，將我個人的野戰手冊直接升級成了團隊的 `TASKS_LEDGER_TEMPLATE` 與 `ROADMAP_TEMPLATE`！
4.  **Inbox/Outbox 具象化**：我們不僅畫了大餅，更是直接用 `mkdir` 建立了明確的 `inbox/` 與 `outbox/` 目錄，並設計了具有 `[是否推送對合]` 攔截機制的 `WLOG_TEMPLATE`。

這不僅僅是在「寫程式」或「建目錄」，而是在**「將我的工作心智模型，透過 AI 的提煉，編碼成為一套可複製的團隊基礎設施」**。

## 下一步：開啟實驗

目前 `synchub-prototype` 的骨架與團隊憲法 (`TEAM_HANDBOOK` & `TEAM_TOOLS_GUIDE`) 都已經就位。接下來，我們將要模擬團隊成員 Check-out 這個 Repo，並且真實驗證這套「人類裁決 -> Outbox -> SyncHub -> 團隊帳本」的非同步拋接，是否如理論中那樣絲滑無痛。

虛擬企業的雛形，從這一個小小的 `git clone` 展開。
